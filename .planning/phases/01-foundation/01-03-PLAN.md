<objective>
Create the shared date and ID utilities used by the DB layer and every screen.

Purpose: the data model keys attendance by a local `YYYY-MM-DD` string and every row by a string ID. A UTC-based key shifts the date after midnight for users behind UTC, creating phantom "yesterday" edits and duplicate-looking records — a direct data-integrity risk (NF-05). Freezing these helpers before the DB layer prevents every DAO from re-implementing date math.
Output: `src/utils/dates.ts` and `src/utils/ids.ts`.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigate |
|-----------|----------|-----------|-------------|----------|
| T-03-01 | Tampering | wrong-date writes from UTC drift | mitigate | `todayKey()`/`toDateKey()` use local `dayjs().format('YYYY-MM-DD')`; a grep gate forbids `toISOString` in the module. |
| T-03-02 | Spoofing | weak/duplicate IDs | mitigate | IDs come from `Crypto.randomUUID()` (expo-crypto), giving 122 random bits; the DB primary key rejects collisions. |
| T-03-03 | Denial of service | invalid date key input | mitigate | Parsing uses `dayjs(key, 'YYYY-MM-DD')`; callers only pass keys produced by these helpers or DB rows (enforced by the DAO layer in plans 01-05/01-06). |
</threat_model>
