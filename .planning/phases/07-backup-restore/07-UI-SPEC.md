## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F0FDFA` light / `#0B1F1D` dark | App background |
| Secondary (30%) | `#FFFFFF` light / `#123330` dark | Cards, picker rows, preview/success cards; hairline `border` `#CCE9E3` / `#205550`; track `muted` |
| Accent (10%) | `#EA580C` light / `#FB923C` dark | See reserved-for list ONLY |
| Destructive | `#DC2626` light / `#F87171` dark | Restore warning text, restore danger-frame border/tint, restore ConfirmDialog confirm text, restore failure text — ONLY |

Accent reserved for: (1) the single full-width backup CTA "Back up now" in the calm backup section; (2) the backup empty-state action button when its section state owns the action (one-orange-per-screen-state rule — the section CTA hides while its empty state shows its own accent action). NOWHERE else: the restore section carries ZERO accent — its pick-file affordance is a `surface` + border + `primary` text row, and its final confirm is text-only `destructive` inside the frozen `ConfirmDialog` (never a filled red button — 02-06 text-only destructive rule). Teal (`primary`/`secondary`) = structure/navigation/section headers/success icon; `STATUS` solids/tints = status only, never reused for backup/restore chrome.

Dark mode: checked independently, never derived by eye. Contrast ≥ 4.5:1 both modes (warning copy, filename text, counts especially).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Back up now" — always verb + noun, never bare "Backup"/"Submit"/"OK". While writing: "Backing up…" (disabled, CR-02 guard discipline). After success the CTA stays mounted for re-backup |
| Restore entry CTA | "Restore from backup" — verb + noun; opens the file picker. NOT orange, NOT destructive-filled: `surface` + hairline border + `primary` text row with `FolderOpen` icon |
| Last-backup line | `caption`/`tabular-nums` beneath backup card title: `"Last backup: {formatDisplay(date)} · {N} worksites · {M} workers · {K} marks"` when a backup has been written this install; `"No backup yet — your data lives only on this phone."` when none (default) |
| Backup success state | "Saved to Downloads" heading + filename in `caption`/`tabular-nums` (`hazra-backup-{yyyymmdd-hhmm}.json`) + counts line from the payload written + two actions: text-primary "Share file" (system share sheet for second-device safekeeping) and muted "Back up again" (resets to idle). Success icon `CheckCircle2`, `primary` teal — never accent |
| Restore pre-pick helper | `caption` muted under "Restore from backup": "Replaces everything on this phone with the backup file. Back up first if you have new marks." |
| Restore validation summary | After a VALID pick, inline confirm card (danger frame, see Layout): `"Backup from {formatDisplay(exported_at)} · {N} worksites · {M} workers · {K} marks — replaces all current data."` + text-only destructive "Replace all data" (opens ConfirmDialog) + muted "Choose a different file" |
| Empty state heading | No data to back up (zero worksites AND zero workers AND zero marks): "Nothing to back up yet" (calm §7.5 pattern) |
| Empty state body | "Add a worksite to get started — backups save everything once there is something to save." + "Add worksite" action → `/worksite-form`. Backup CTA hidden in this state (one-orange rule). Never a dead CTA |
| Error state (backup failure) | "Couldn't back up — try again" (`destructive` text) + "Try again" retry (CR-01/CR-02 discipline: guard reset, no partial file left behind). Storage variant: "Couldn't save the file — check storage space and try again" |
| Error state (restore validation) | Problem + solution path, `destructive` text, data untouched, dialog NEVER opens: truncated/corrupt JSON → "That file looks damaged — pick a complete backup file."; missing `attendance` key (or any required key: `version`/`exported_at`/`worksites`/`workers`/`attendance`) → "That file isn't a Hazra backup — pick a file saved by Back up now."; unknown `version` → "That backup is from a newer app version — update the app, then try again." Each with a "Choose a different file" retry action |
| Error state (restore write failure) | "Couldn't restore — your current data is unchanged. Try again" + "Try again" retry (transaction rolled back, counts re-read to prove intact) |
| Destructive confirmation | Restore: ConfirmDialog title "Replace all data?" · message "This erases everything currently on this phone — worksites, workers, and all attendance marks — and replaces it with the backup from {date}. Removed workers and history included in the backup come back; anything added after that backup is lost forever. This cannot be undone." · confirmLabel "Replace all data" (text-only `destructive`, never filled) · cancel default (backdrop press + Cancel + hardware back all abort, nothing written). Exact date injected via `formatDisplay`, never raw ISO |
| Post-restore success | "Restore complete" + `"Restored {N} worksites · {M} workers · {K} marks"` (`tabular-nums`) + muted "Back to safety" dismiss (no auto-navigation; screen refetches counts). No accent element in this card |

## Backup Layout (BK-01..BK-03)

`src/app/backup.tsx` (placeholder) becomes the single drill-down safety-net route. NO tab changes (4 tabs max — design §8/§10). Order top→bottom inside a `ScrollView` (16px gutters on children, `MaxContentWidth` 800 centered):

1. **Screen title** (`h1` 28/700): "Backup & Restore". Beneath, muted `caption`: "Your only safety net — keep a copy outside this phone."
2. **Calm backup section** (BK-01 · default):
   - Flat card (`Radius.md`, 16px padding, hairline border, `surface` fill): `h2` "Back up" + `Download` icon (`primary` teal), body line "Saves everything — worksites, workers, and all attendance marks, including removed ones — to one file in Downloads.", last-backup line (`caption`/`tabular-nums`), counts preview line when data exists.
   - One orange CTA: full-width "Back up now" → serialize → write → success card. Writing state: inline progress row (indeterminate skeleton bar + "Backing up…" label, CTA disabled with CR-02 re-entry guard — double-tap produces exactly one file).
   - Success card (replaces preview area after write): "Saved to Downloads" + filename (`caption`, `tabular-nums`) + payload counts line + "Share file" (primary text → system share sheet) + muted "Back up again" (resets to idle). Failure path: `destructive` "Couldn't back up — try again" + "Try again" retry; no partial file retained.
   - Zero-data state: preview/CTA replaced by the calm no-data empty lines + "Add worksite" accent action (one-orange rule).
3. **Divider**: 24px gap + 1px `border` hairline. No accent element crosses the divider — the screen reads as two moods.
4. **Danger-framed restore section** (BK-02/BK-03 · default):
   - Danger card (`Radius.md`, 16px padding, `surface` fill, 1px `destructive`-tinted border + `TriangleAlert` icon in `destructive`): `h2` "Restore" + body warning "Replaces everything on this phone with a backup file. Cancel keeps your current data — cancel is always the safe choice."
   - "Restore from backup" pick-file row (`surface` + border + `primary` text, 44px target): opens the document picker filtered to JSON. Picking a file validates the ENTIRE payload in memory first (shape: `version` known == 1, `exported_at` string, `worksites`/`workers`/`attendance` arrays; row-level required keys per PRD §8) — the DB is never touched before validation passes.
   - Valid pick → inline validation-summary card (same danger frame) with counts + text-only destructive "Replace all data" (opens frozen `ConfirmDialog` with the exact copy above) + muted "Choose a different file". Cancel/backdrop/back aborts with zero writes.
   - Confirm → single-transaction replace (delete-all + re-insert incl. inactive rows, FK order worksites → workers → attendance) → "Restore complete" card + screen refetch. Any failure → restore error state, data proven intact by re-read counts.
   - Invalid pick → the matching validation error state (three mapped copies above), data untouched, dialog never opens.

Payload contract (BK-03 · default): `{ version: 1, exported_at: <local ISO-ish key, never bare toISOString drift>, worksites: [...all rows incl. is_active=0], workers: [...all rows incl. is_active=0], attendance: [...all rows] }`. Filenames (Downloads): `hazra-backup-{yyyymmdd-hhmm}.json` (lowercase, no spaces). Files open/parse outside the app (NF-06): plain UTF-8 JSON, opens in any text editor after share-sheet transfer.

## Interaction Contracts

| Contract | Rule |
|----------|------|
| Backup guard | `backingUp` boolean re-entry guard (CR-02 + 06-06 finally-only-reset precedent): every early return from the locked section sits inside `try`; `finally` is the only reset path. CTA disabled + "Backing up…" while writing; concurrent taps collapse to one file |
| Restore validate-before-touch | Full in-memory validation BEFORE any DB write: JSON parse → required top-level keys → `version` allowlist → array shapes → row-level required fields. ANY failure → mapped error copy, zero writes, dialog never opens. Success criterion #3 (truncated / missing-`attendance` / unknown-version) each has its own copy + "Choose a different file" |
| Restore transaction | Confirm → one SQLite transaction: delete attendance → workers → worksites, then re-insert in FK order worksites → workers → attendance (inactive rows preserved as-is). Rollback on ANY write error → "Couldn't restore — your current data is unchanged" + re-read counts as intact proof. Success criterion #2 |
| Restore cancel-default | Frozen `ConfirmDialog`: backdrop press + Cancel + hardware-back (`onRequestClose`) ALL abort with zero writes. The confirm label is text-only `destructive` — never a filled red button. Success criterion #4 |
| Counts honesty | Last-backup line, preview lines, success cards, and validation summary all read from the SAME DAO/live-query scope as the file bytes or parsed payload — never client math or stale props. Round-trip (backup → clear → restore) reproduces counts + sample statuses (success criterion #5) |
| Loading | Skeleton blocks matching card height on first load (profile `StatsSkeleton` precedent); pick/validate shows skeleton over the restore card only, backup section stays mounted — never spinner swap or blank flash |
| Failure | All `async` flows try/catch-inside + mapped copy + retry (CR-01/CR-02). Partial files deleted on failure, never surfaced. Restore write failure re-reads live counts to prove data intact |
| Share flow | Success card "Share file" → system share sheet. Share-sheet dismiss changes nothing. Downloads save is the source of truth; share is the safekeeping/transfer path |
| Focus / refetch | `useFocusEffect(useCallback(...))` refetch of live counts + last-backup line so register corrections reflect on back (04-02 precedent) |
| Pressables | `Pressable` ONLY (no `TouchableOpacity`); ripple + opacity 0.85; 44px targets, ≥8px gaps; `accessibilityLabel` on icon-only controls; validating/restoring states announce via polite live region ("Validating backup…", "Restore complete …"); focus outline uses `ring` token |
| Flat + one-orange | No shadows/gradients/glassmorphism — 1px `border` + surface/background contrast only. Exactly ONE orange element per screen state: the "Back up now" CTA (or its empty-state action). The restore half of the screen contains zero orange by construction |
| Never color-alone | Warning/success/validation states always pair icon + label text with color; counts always numerals + labels; contrast ≥ 4.5:1 both modes |

## Accessibility + Motion + Dark Mode

- **A11y:** section headers are real headings; pick-file row + CTA carry `accessibilityLabel` + `hitSlop`; validation/success/error regions announce via polite live region; destructive confirm is text + explicit copy, never color-alone; focus outline uses `ring` token; contrast ≥ 4.5:1 both modes.
- **Motion:** 150–300ms, ease-out enter / ease-in exit; opacity + transform only (success/validation card fade/slide-in; skeleton shimmer via opacity only). Respect `AccessibilityInfo.isReduceMotionEnabled()` — skip animations, keep state changes. No decorative-only animation.
- **Dark mode:** every token pair above; the JSON file content is theme-independent (plain UTF-8); check independently on-device. Never hardcode hex in components — always `useTheme()` / token (DS-03 gate).
