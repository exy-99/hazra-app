<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| verified private archive → transfer channel | The accepted bytes can be substituted or corrupted during packaging/transfer. |
| sender manifest/hash → recipient computation | Independent checksum verification establishes received-file integrity. |
| credential vault → manager bundle | Signing secrets must never cross into distribution. |

| Threat ID | Category | Threat | Disposition | Concrete mitigation and verification | Owner | Residual risk |

| T-09-P08-02 | Spoofing | Wrong EAS project/credential lineage is represented to manager. | mitigate | Manifest carries build ID/source/package/cert; all must match H2-H4/H7 and tested evidence. | human | Manager generally trusts supplied build metadata; signature/hash records enable later audit. |
| T-09-P08-03 | Tampering / DoS | Package/signing/version drift breaks a later sideload update and risks data loss. | mitigate | Manifest captures package/cert/versionCode; guide requires same key/package, higher versionCode, backup first, install over existing, and no uninstall on conflict. | human | A future release operator can still ignore instructions; custodian escalation is explicit. |
