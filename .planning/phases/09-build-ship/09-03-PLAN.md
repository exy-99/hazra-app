## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository template → user private archive | Blank contracts become human-completed evidence and handoff files outside Git. |
| tested APK → manager | The delivered bytes and checksum must remain identical to the UAT candidate. |
| test device → backup/restore inputs | Destructive and malformed-file proofs can affect local SQLite state. |

## STRIDE Threat Register

| Threat ID | Category | Threat | Disposition | Concrete mitigation and verification | Owner | Residual risk |
|-----------|----------|--------|-------------|--------------------------------------|-------|---------------|
| T-09-P03-01 | Information Disclosure / DoS | Keystore/password is disclosed in evidence/handoff or recovery material is lost. | mitigate | Both templates forbid passwords/private bytes/tokens and separate credential vault from manager bundle; H2 requires a non-secret custody reference and encrypted recovery copy. Content checks require exclusion text. | agent for templates; human for custody | The private vault implementation is chosen and operated by the user. |
| T-09-P03-02 | Spoofing | Wrong EAS owner/project/credential linkage is accepted. | mitigate | H1 fields require owner, UUID, dashboard URL, and linkage decision; H2 fingerprint/custodian fields join that identity before build. All start `NOT RUN`. | human | Repository fields cannot independently authenticate remote ownership. |
| T-09-P03-03 | Tampering / DoS | Package/signing/version drift breaks updates and risks data loss. | mitigate | Manifest and update blocks lock package/version, actual remote versionCode, certificate fingerprint, backup-first, install-over-existing, and no-uninstall rules. | agent for contract; human for actual values | Recipient behavior can still violate instructions; checksum/custodian escalation reduces risk. |
