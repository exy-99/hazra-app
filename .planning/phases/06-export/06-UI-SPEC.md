## Export Layout (EX-01..EX-03 · defaults D-01..D-10)

`src/app/export.tsx` (placeholder) becomes the single drill-down export route, pushed from Reports per-worker rows and/or worksite context. NO tab changes (4 tabs max — design §8/§10). Order top→bottom inside a `ScrollView` (16px gutters on children, `MaxContentWidth` 800 centered):

1. **Screen title** (`h1` 28/700): "Export". Beneath, muted `caption`: "Payroll-ready files saved to Downloads."
2. **Scope switcher** (default): two-option segmented control — "Worker" | "Worksite month" (`label` 14/600, 44px targets, ≥8px gaps, `radio` role). Preselect from push params when present (`?workerId=`, `?worksiteId=&month=`); params are display strings at the route boundary, bound as `?` params downstream, never interpolated (01-08 T-08-01 precedent).
3. **Worker scope section** (when "Worker" selected · EX-01):
   - Worker picker: active-only worker rows (memo `FlatList`, `keyExtractor` on id, name + `role · site` second line, `radio` role) reusing 02-04 list language. Removed workers reachable by deep-link id still exportable (history preserved — PRD §9). Zero active workers → "No workers at this worksite" + "Add worker" → `/worker-form`.
   - Range display: fixed full-history export (no custom range in v1 — keep it payroll-simple); caption shows `"All recorded history · N days"` via `getAttendanceForWorker(id)` + `summarize()`.
4. **Worksite scope section** (when "Worksite month" selected · EX-02):
   - Worksite picker: All-sites excluded — exactly one active worksite (radio rows, default first active; 02-04 `__all__` pattern NOT reused here because a register is per-site).
   - Month picker: month-grid sheet reusing the DateStrip calendar modal (fixed rows, sibling absolute-fill `Pressable` scrim, local date keys only, never `toISOString`; future months never selectable — 05 D-09 precedent). Label: `"Month: {Month Year}"` with `CalendarDays` affordance.
5. **File-type choice** (both scopes): CSV / PDF segmented chips (default CSV). Selected = `primary`-tinted surface + `foreground` text; never accent fill.
6. **Preview + row-count confirmation** (both scopes): flat preview card (`Radius.md`, 16px padding, hairline border, `surface` fill) showing the row-count line + up to 5 sample rows (date + STATUS-tint read-only chip + note truncated `numberOfLines={1}` — 04-03 HistoryRow read-only language, never `StatusPill`). PDF scope additionally shows a mini legend row (4 STATUS dots + labels — never color alone). Zero countable rows → preview card replaced by the calm no-action empty line and CTA disabled.
7. **One orange CTA** per scope state: full-width "Export worker history" / "Export monthly register" → generate → save → success card. Generating state: inline progress row (indeterminate skeleton bar + "Exporting…" label, CTA disabled with `saving`-style re-entry guard — CR-02 discipline; double-tap produces exactly one file).
8. **Success card** (replaces preview card after generation): "Saved to Downloads" + filename (`caption`, `tabular-nums`) + "Share file" (primary text, opens system share sheet — EX-03 second-device transfer path) + muted "Export another" (resets to picker). Failure path: `destructive` "Couldn't export — try again" + "Try again" retry; no partial file retained.

CSV contract (EX-01/EX-02/NF-06): RFC-4180 — comma delimiter, CRLF or LF rows, header row, every field containing `,`/`"`/newline quote-wrapped with `"` doubled. Worker CSV columns: `date,status,note`. Worksite-monthly CSV columns: `date,worker,status,note` sorted by date then worker name. Status values are lowercase keys (`present/absent/half_day/off_day`) — machine-parseable. The roadmap probe note (`left early, told "back tomorrow"`) must round-trip to the correct column count in Excel/Sheets (success criterion #1).

PDF contract (EX-01/EX-02/NF-06): single HTML table via `expo-print` — title line (`{Worker name} attendance` / `{Site name} register · {Month Year}`), column headers, one row per entry (date via `formatDisplay`, STATUS label text + tinted cell, note or `—`), footer summary line from `summarize()` (`P present · A absent · H half day · O off day · N%`), legend row (4 STATUS dots + labels). `tabular-nums` on all numerals. Must open in any PDF viewer after transfer (success criterion #3).

Filenames (Downloads): `hazra-worker-{slug}-{yyyymmdd}.csv|pdf` · `hazra-register-{siteslug}-{yyyymm}.csv|pdf` (lowercase slugs, no spaces). Files land in Downloads and open correctly on a second device after share-sheet transfer (success criteria #2/#3).

## Interaction Contracts

| Contract | Rule |
|----------|------|
| Entry points | Push from Reports per-worker rows (`?workerId=`) and/or worksite context (`?worksiteId=&month=`); direct `/export` opens scope-switcher default "Worker". No tab changes |
| Scope retention | Scope switcher is sibling state (`selectedScope` next to `selectedWorker`/`selectedSite`/`selectedMonth`); switching scope preserves the other scope's picks structurally (03-05 retention precedent). Switching scope/file-type never clears the success card of the other scope — each scope owns its own preview/success/error state |
| File-type retention | `selectedFormat` sibling state; switching CSV↔PDF keeps scope picks and re-renders preview only (no refetch) |
| Generating guard | `exporting` boolean re-entry guard (CR-02): CTA disabled + "Exporting…" label while generating; concurrent taps collapse to one file. Failure resets guard + shows retry; success resets guard + shows success card |
| Loading | Skeleton blocks matching preview-card height on first load (profile `StatsSkeleton` precedent); scope switches show skeleton over preview only, pickers stay mounted (05 D-10 precedent) — never spinner swap or blank flash |
| Failure | `export()` try/catch-inside + "Couldn't export — try again" + "Try again" (CR-01/CR-02). Load failure of pickers: "Couldn't load …" + "Try again" EmptyState. Partial files deleted on failure, never surfaced |
| Share flow | Success card "Share file" → `expo-sharing` system sheet (`shareAsync`). Share-sheet dismiss changes nothing (StatusPill close-without-pick precedent). Downloads save is the source of truth; share is the transfer path (EX-03) |
| Focus / refetch | `useFocusEffect(useCallback(...))` refetch of picker lists + preview counts so register corrections reflect on back (04-02 precedent). Preview counts and file content come from the SAME DAO scope — never client math |
| Pressables | `Pressable` ONLY (no `TouchableOpacity`); ripple + opacity 0.85; 44px targets, ≥8px gaps; `accessibilityLabel` on icon-only controls (month-picker affordance, share button); status never color-alone (STATUS label text always, PDF legend labeled) |
| Flat | No shadows/gradients/glassmorphism — 1px `border` + surface/background contrast only. One orange element per screen state (02-02 one-orange rule) |

## Accessibility + Motion + Dark Mode

- **A11y:** scope switcher + file-type chips carry `radio` role + selected state; every STATUS chip labeled with text (never color alone); month-picker and share icon-only controls get `accessibilityLabel` + `hitSlop`; generating state announces via polite live region ("Exporting…", then "Saved to Downloads {filename}"); focus outline uses `ring` token; contrast ≥ 4.5:1 both modes.
- **Motion:** 150–300ms, ease-out enter / ease-in exit; opacity + transform only (success-card fade/slide-in; skeleton shimmer via opacity only). Respect `AccessibilityInfo.isReduceMotionEnabled()` — skip animations, keep state changes. No decorative-only animation.
- **Dark mode:** every token pair above; PDF HTML uses explicit light-register styling (white table, dark text) regardless of app theme so the file reads identically everywhere; check independently on-device. Never hardcode hex in components — always `useTheme()` / token (DS-03 gate).
